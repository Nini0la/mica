## Reproduce the deployment

1. Create a separate PostgreSQL database named `mica_judge_demo` and a login role named
   `mica_judge` that owns only this demo database. Do not grant it membership in private database
   roles. Apply migrations using this restricted role. Verify it cannot read any private tables.
   On Neon, the administrator may need membership **in the demo role** to create a database owned
   by that role; never grant the reverse membership.
2. Copy `.env.judge.example` to ignored `.env.judge`. Supply a random judge access code, independent
   session secret, restricted demo database URL, Nebius key and optional Tavily key. Leave all
   Telegram/WhatsApp credentials blank. Set the exact HTTPS origin generated by Modal.
3. From `backend/`, run `uv sync --extra dev` and
   `uv run --env-file ../.env.judge alembic upgrade head`.
4. From the repository root, seed only synthetic records:
   `PYTHONPATH=backend uv run --project backend --env-file .env.judge python deploy/seed_judge.py`
   Alternatively load `.env.judge` using your environment manager and run `deploy/seed_judge.py`
   with `PYTHONPATH=backend`. Seeding is idempotent and refuses non-judge database names/roles.
5. From `frontend/`, run `npm ci`, then:
   `MICA_STATIC_EXPORT=1 NEXT_PUBLIC_API_URL='' NEXT_PUBLIC_JUDGE_DEMO=1 npm run build`.
   This creates `frontend/out/`; the browser uses relative `/api` requests on the same HTTPS origin.
6. From the repository root:
   ```sh
   backend/.venv/bin/python deploy/prepare_judge.py --env-file .env.judge
   modal secret create mica-judge-runtime --from-json .local/judge-runtime.json --force
   modal deploy deploy/modal_judge.py
   ```
7. Check the actual emitted Modal URL. If it differs from the configured origin, update the
   private configuration/Secret and run `modal app rollover mica-judge-demo --strategy recreate`.
8. Verify `/api/demo/status`, a fresh-browser login, a real chat/tool call and an unattended reminder.
   Record the source revision and returned provider/model. Use the existing inspector for evidence.

Use the exact code revision in EVIDENCE.md for the submitted build. Do not redeploy unverified
optional work over the judging instance. Images include source and static assets, never `.env`,
database dumps, local rollout artifacts or the developer's home directory.

## Availability and cost controls

One personal scheduler wakes every 30 seconds with 0.125 requested CPU cores/256 MiB and a
single-container cap. Two web containers maximum, each requesting 0.25 CPU cores/512 MiB,
scale down after 60 seconds idle. No GPUs or stored model weights are used. An hourly expiry
function stops only the demo app after the configured demonstration end; mutation guards block
new demo writes after the cutoff. Keep the code expiry and Secret cutoff aligned when changing it.

Inference remains bounded at two calls/turn, 15 seconds/call and 2,400 output tokens/call.
Tavily uses basic Search (one credit) and at most one basic Extract (provider meters successful
URL batches); reported usage is recorded, not assumed. Costs depend on actual judge usage.
Keep provider accounts funded/credited through judging; no software deployment can guarantee
availability if third-party quota or billing is exhausted.

## Recovery

- The authoritative state is in Neon. Redeploying/rolling over containers does not reset it.
- Redeploy the last verified source revision, rebuild its static export and verify health.
- Keep **one** scheduled `scheduler` function for this demo; do not start a second poller against
  the same database. Existing database action keys/leases protect retries and duplicate effects.
- Do not restore private-owner data into the demo. Seed only the supplied synthetic fixture.
- Back up the demo with a PostgreSQL version compatible with the server before destructive reset
  or migration. There is no public reset endpoint. Preserve judge traces before any operator reset.
- The runtime accepts manually selected Azure configuration in ordinary private deployments,
  but the judge configuration deliberately requires Nebius/NVIDIA. Do not silently substitute Azure
  for a failed qualifying-model demonstration.
- To stop only the demo: `modal app stop mica-judge-demo --yes`. This does not stop the private
  assistant or delete the database. Do not stop it during judging unless restoring service.
